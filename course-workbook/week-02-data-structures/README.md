# Week 02 — Data Structures and Collection Processing

## Objective

Understand how Python's built-in collections represent and organize related values, and how to process those collections clearly and safely.

The focus is on choosing an appropriate structure, understanding its behavior, and explaining the trade-offs — not memorizing methods.

## Weekly Outcome

Build a task collection processor that stores task information in suitable data structures, iterates and transforms collections, and handles expected errors explicitly.

By the end of the week, I should be able to implement and explain the solution independently, using the Data Structures section of the Pro Python course.

## Learning Outcomes

By the end of the week, I should be able to:

- [ ] Explain the differences between tuples, sets, dictionaries, and lists, and choose an appropriate structure for a problem.
- [ ] Describe collection ordering, uniqueness, mutability, and key lookup behavior.
- [ ] Iterate through collections and select the appropriate iteration pattern.
- [ ] Use comprehensions to transform or filter collections when they improve clarity.
- [ ] Explain how exceptions propagate and handle expected errors with specific exception types.
- [ ] Explain the purpose of context managers and the `with` statement.
- [ ] Explain what decorators do at a high level and identify their basic syntax.
- [ ] Integrate collection processing into a small, runnable task report.

## Exercise Requirements

Each exercise should:

1. Address a specific learning outcome.
2. Be implemented independently before consulting a solution.
3. Include experiments with alternative inputs or edge cases.
4. Produce observable behavior that can be verified.
5. Be explainable without relying on memorized syntax.

## Constraints

- Build on concepts from Week 01.
- Use only concepts introduced so far, unless an experiment explicitly calls for further investigation.
- Prefer the simplest implementation that satisfies the exercise.
- Avoid unnecessary dependencies and application scaffolding.
- Do not add abstractions simply to make the exercise look production-ready.
- Treat starter comments as prompts, not requirements to implement everything at once.

## Definition of Done

- [ ] All five exercises have working implementations.
- [ ] The weekly learning outcomes have been assessed honestly.
- [ ] Collection behavior and relevant edge cases have been explored.
- [ ] Expected invalid inputs are handled deliberately, without hiding unrelated errors.
- [ ] The final report can be explained and modified independently.
